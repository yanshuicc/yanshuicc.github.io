# 多种文章风格
对于博客的布局，分别设置了中篇文章、大纲文章、短篇文章3种布局，layout设定分别对应article、outlined、eassy。中篇文章一般是500-1000字左右，长篇文章一般采用大纲，短篇是100-500字的临时想法记录。3种布局共用同一套视觉语言，分别是灰白黄、浅灰卡片、细边框、赭黄点缀，只在宽度、留白、元素密度上区分。


## 适配屏幕尺寸

在需求上希望考虑适配常见分辨率和屏幕尺寸的设备屏幕。这里涉及硬件物理层面的概念、系统逻辑层面、网页逻辑层面的概念。

### 硬件层面屏幕相关概念

1. 屏幕尺寸：屏幕对角线的物理长度，单位是英寸（inch）。需要注意的是屏幕尺寸只描述物理对角线长度，不直接决定清晰度。同样 27 英寸，1080P 和 4K 的细腻程度差别很大，所以需要结合分辨率看 PPI。
2. 物理分辨率：设备屏幕的像素数量，屏幕是由一个个发光点组成的，发光点就是一个物理像素（device pixel），无法通过软件改变。它是硬件层面的最小显示单元，无法显示半个物理像素。比如 1920×1080，意思是横向 1920 个发光点、纵向 1080 个发光点，总共约 207 万个。
3. PPI（Pixels Per Inch，每英寸像素数）：PPI 衡量的是硬件层面的像素密度，决定了屏幕在物理上能细腻到什么程度，决定了屏幕画面物理细腻程度、颗粒感。

### Windows层面屏幕相关概念
在软件层面，考虑以下几个概念：

1. 逻辑像素（DIP，Device-Independent Pixel，设备无关像素）：是指系统或软件布局和绘制时的最小单元，或者系统或软件认定的设备屏幕大小。在 Windows 开发中，DIP 与物理像素的换算关系是：DIP = 物理像素 × 96 / DPI。在 Web 前端语境里，当页面缩放为 100% 时，1 个 CSS 像素通常就对应 1 个 DIP。
2. 逻辑分辨率：逻辑分辨率则是用 DIP 为单位表示的屏幕或视口尺寸，比如 1920×1080 个 DIP，其单位是逻辑像素。
3. DPI（Dots Per Inch，每英寸的逻辑像素）：在 Windows 显示设置语境里，表示系统在逻辑层面每英寸安排多少个 DIP。
Windows 以 96 DPI 对应 100% 缩放作为基准。当缩放 100% → DPI = 96，此时，系统认为每英寸在逻辑时配置96个逻辑像素，1个逻辑像素对应1个物理像素。缩放 125% → DPI = 120，此时，系统认为每英寸在逻辑时配置120个逻辑像素，1个逻辑像素对应1.25个物理像素。可以依次类推，缩放 150% → DPI = 144，缩放 200% → DPI = 192。
4. 系统缩放比：一般来说1080P屏幕的DPR是1或1.25，Windows下1.25和1.5非常常见，由于不是整数倍，程序实际渲染时，可能取整和抗锯齿导致出现模糊感，4K屏幕采用1.5倍（ 27 英寸）/2倍（24英寸）缩放，MacBook、手机的缩放比是2，在手机上 2K 的像素密度已经超过肉眼能分辨的精细程度，300 PPI 是一般观看距离下的经验阈值，2K 手机 PPI 通常 400-500+，4K 在手机上的收益很小，反而更耗电，所以厂商普遍不热衷。

```
# Windows开发的逻辑像素
DIP = 物理像素 × 96 / DPI
PPI = √(横向像素² + 纵向像素²) ÷ 屏幕尺寸
```
### 网页层面屏幕相关概念
对于网页端，适配窗口大小无需考虑屏幕的物理尺寸，应该考虑CCS宽度。

1. DPR（Device Pixel Ratio，设备像素比）是web开发中的概念，表示一个 CSS 像素对应多少个物理像素。默认等于系统缩放比，但是实际情况会叠加一个浏览器缩放。
1080P分辨率宽1920，DPR为1时，CSS宽度为1920；4K分辨率显示器宽3840，DPR为1.5时，CSS宽度为2560；4K分辨率显示器宽3840，DPR为2时，CSS宽度为1920
2. CSS宽度：浏览器视口（viewport）的宽度，用 CSS 像素来度量，即web中的px。


```
DPR = 屏幕PPI ÷ 系统缩放比
CSS 宽度 = 物理分辨率 ÷ DPR
```

### 常见桌面分辨率

| 分辨率 | 俗称 | 市场情况 |
|---|---|---|
| 1920×1080 | 1080P / FHD | 绝对主流，约一半用户 |
| 2560×1440 | 1440P / 2K | 增长最快的升级方向 |
| 2560×1600 | 16:10 2K | 笔记本常见 |
| 3840×2160 | 4K | 占比仍低，受成本和缩放习惯限制 |
| 3440×1440 | 带鱼屏 | 小众但稳定 |

| 设备 | 物理分辨率 | DPR | CSS 宽度 |
|---|---|---:|---:|

| 4K 显示器 150% 缩放 | 3840×2160 | 1.5 | 2560 |
| 4K 显示器 200% 缩放 | 3840×2160 | 2 | 1920 |
| MacBook Pro 14" | 3024×1964 | 2 | 1512 |

# 代码样式

## highlight和围栏代码块的区别

两者都能渲染代码，但走的路径不同，能力上有一些细节差异。

围栏代码块是Markdown 原生能力。
````markdown
```go
func main() {
    fmt.Println("hi")
}
```
````

生成的代码如下：
```
<div class="language-go highlighter-rouge">
  <div class="highlight">
    <pre class="highlight"><code>...</code></pre>
  </div>
</div>
```
highlight 标签Jekyll的Liquid模板语法
```{% raw %}
{% highlight go %}
func main() {
    fmt.Println("hi")
}
{% endhighlight %}{% endraw %}
```

highlight 标签生成：
```
<figure class="highlight">
  <pre><code class="language-go" data-lang="go">...</code></pre>
</figure>
```

异同：
* Liquid 标签。Jekyll 会先解析 Liquid，处理Liquid代码标签逻辑再渲染 Markdown。围栏代码块不做处理直接输出。
* 围栏代码块想开行号，需要在 _config.yml 里全局设置：

```yaml
kramdown:
  syntax_highlighter_opts:
    block:
      line_numbers: true
```
或者
````markdown
```go
func main() {}
```
{: .no-lineno}
````

Liquid可以在代码块中指定
```
{% raw %}{% highlight go linenos %}
{% endhighlight %}{% endraw %}
```

# 当前页面屏幕/视口诊断

> 以下数值由浏览器在页面加载时实时写入，打开本页即可看到你当前设备的实际值。
>
> **注意**：`screen.width` 返回的是**逻辑分辨率（CSS 像素）**，受系统缩放比影响。
> 真实物理像素 = 逻辑分辨率 × `devicePixelRatio`。浏览器最大化时 `innerWidth` 才接近 CSS 宽度。

<div id="screen-diagnostics" style="margin: 2em 0; padding: 16px 20px; background: #F5F2EA; border: 1px solid #E8E3D8; border-radius: 4px; font-family: Consolas, monospace; font-size: 13px; color: #3A3A38; line-height: 1.8;"></div>
<script>
(function() {
    var out = document.getElementById('screen-diagnostics');
    if (!out) return;
    var d = document.getElementById('content');
    var dr = d ? d.getBoundingClientRect() : null;
    var sx = screen.width, sy = screen.height, r = window.devicePixelRatio;
    out.innerHTML =
        '┌─ 物理像素（屏幕真实发光点） ────────────────<br>' +
        '│  physical 宽  = ' + Math.round(sx * r) + ' px &nbsp;&nbsp;(' + sx + ' × DPR ' + r + ')<br>' +
        '│  physical 高  = ' + Math.round(sy * r) + ' px &nbsp;&nbsp;(' + sy + ' × DPR ' + r + ')<br>' +
        '├─ 系统逻辑分辨率（CSS 像素） ────────────────<br>' +
        '│  screen.width  = ' + sx + ' px<br>' +
        '│  screen.height = ' + sy + ' px<br>' +
        '│  devicePixelRatio = ' + r + '<br>' +
        '├─ 当前浏览器窗口 ────────────────────────────<br>' +
        '│  innerWidth  (CSS 视口) = ' + window.innerWidth  + ' px<br>' +
        '│  innerHeight            = ' + window.innerHeight + ' px<br>' +
        '│  outerWidth  (含边框)   = ' + window.outerWidth  + ' px<br>' +
        '│  html.clientWidth       = ' + document.documentElement.clientWidth + ' px<br>' +
        '├─ 本页 #content 元素 ──────────────────────<br>' +
        '│  渲染宽 = ' + (dr ? Math.round(dr.width) : 'N/A') + ' px<br>' +
        '│  左偏距 = ' + (dr ? Math.round(dr.left)  : 'N/A') + ' px<br>' +
        '│  body 宽 = ' + document.body.clientWidth + ' px<br>' +
        '└─────────────────────────────────────────────';
})();
</script>

**换算公式回顾**

```
物理分辨率 = screen.width × devicePixelRatio       ← 屏幕真实像素，4K屏会显示 3840×2160
逻辑分辨率 = screen.width                          ← CSS 像素，受系统缩放影响（4K 150% 缩放 = 2560）
CSS 视口宽 = window.innerWidth                     ← 当前浏览器窗口 CSS 宽（窗口非最大化时 ≠ 屏幕）
DPR        = 浏览器缩放 × 系统缩放比
内容最佳宽  ≈ 720 px（英文 ~80 词/行，中文 ~36 字/行）
```
